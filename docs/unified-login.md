# 阿瓦隆统一登录与 PostgreSQL

核对日期：2026-10-16。状态：配置中。本次用户决定优先于旧文档的 SQLite 部署约定：正式房间、会话、命令回执和认领事实使用独立 PostgreSQL 数据库与角色，旧 SQLite 卷保留且不自动迁移演示身份。原卡面、中文规则与可信离线房主模式不改变。

## 权限与存储

在线访客仍可直接开桌。已有中央登录态自动识别，同账号在新设备恢复同一个玩家及其在线座位，不获取别人的身份。浏览器只收到逐人投影，不收到内部账号主键或服务端会话哈希。SSE 发布及心跳重新检查账号权限；退出或切换账号会关闭原在线连接，旧异步响应不能写回新身份。

登录前的游客座位只在原浏览器保留。首页可先预览，再明确确认认领，每个账号在阿瓦隆仅一次。预览签名绑定账号、游客能力凭证、房间版本和有效期；取消不扣次数，账号已有牌桌拒绝覆盖。确认与认领事实在同一 PostgreSQL 事务提交；丢失响应时重试同一确认幂等，失败不留下数据库认领记录。正常账号对局无限次。

离线扫码的整局隐藏角色与配对证明留在可信房主设备，不上传、不转成在线权威牌局。网页账号切换不修改正在主持的离线牌桌。Service Worker 明确排除业务 API、账号路由与登录回调，不缓存私人投影或认证页面。

## 发布与恢复

业务提交检查后推送并合并 `Max0314/avalon` 主分支。私有运维仓库注册 `avalon` 应用、精确回调、数据库角色与 Nginx 同源账号路径；配置只存 `/etc/fribench/apps/avalon/app.env`，保留其他设置并增加 `DATABASE_URL` 与应用独立密钥，不输出原文。

固定完整提交，构建 `fribench-avalon:<SHA>`，使用 `compose.prod.yaml` 设置 `AVALON_IMAGE` 和 `AVALON_RELEASE`，先配置校验，再只更新 app。继续使用回环 23010，独立 Compose 项目，256MiB/0.5CPU/64PIDs，只读非 root 容器。PG 与身份网均为外部专网；数据库不映射公网。

单写数据库锁禁止并行权威进程。提交成功后才返回成功和广播；持久化失败停止发布，正式进程退出后由 Compose 重启并加载已提交状态。旧镜像不作为长期恢复依赖，需要恢复代码时从已推送提交重建；不得清理数据卷。现行数据备份应使用平台 PostgreSQL 逻辑备份，旧 `tools/backup.mjs` 仅适用于遗留 SQLite。

`npm run check` 校验规则、权限、HTTP、存储和构建。`TEST_DATABASE_URL` 必须指向隔离测试 PostgreSQL：测试创建自己的随机 schema，验证账号恢复、隔离、唯一认领、事务回滚和重启，结束只移除自己的 schema。浏览器验收通过桌面工具执行，不用测试后门或真实用户密码。
