# 上游审计与改造记录

核对日期：2026-10-15。审计对象为 `aglinaodan/avalon` / 用户 fork 的 `4efb49f36fbf71dcdf6f008c6feb0cf0d4e44121`，引用的函数和行为均指该历史版本。结论用于判断能否直接部署到 Fribench，并非对作者后续版本的判断。

| 优先级 | 上游行为与触发 | 影响 | 本版处理 |
| --- | --- | --- | --- |
| P0 | `loadGameState` 和房间订阅读取整个房间，包含 `roles`、个人 `questCards` | 任意玩家通过开发者工具获知全员身份及任务出牌 | 服务端逐人投影，只发本人角色/应知情报；终局才公开角色；个人任务牌始终不公布 |
| P0 | 浏览器直接更新 Firebase 房间状态 | 可绕过按钮限制修改阶段、身份或结果 | 服务端白名单命令、身份/阶段/席位校验、数据库事务；不接受客户端胜负和身份字段 |
| P1 | `performAccountLogin` 使用浏览器内的管理账号/PIN，普通 PIN 为弱口令并可由客户端访问 | 不能作为公网账号系统 | 移除上游账号和管理后门；访客随机 Cookie，服务端仅存哈希，房间码与座位凭证分离 |
| P1 | 多处昵称经 `innerHTML` 拼接 | 可插入非预期 HTML | 服务端昵称验证，前端所有动态玩家文本转义，严格同源 CSP |
| P1 | `questFailsRequired` 的双失败门槛放在索引 4；实际使用零基轮次 | 7 人以上第四轮错误，影响胜负 | 索引 3 双失败；第四/第五轮分别回归 |
| P1 | 好人交失败主要依赖前端提醒 | 可绕过规则 | 规则层拒绝好人失败牌和非队员出牌 |
| P1 | 关闭身份弹窗直接将本地阶段设为 `nominate` | 未确认身份时提前组队 | 关闭仅隐藏；全员独立确认后服务端推进 |
| P2 | 5/6 人局多选特殊邪恶角色后静默截断 | 玩家以为已启用的角色实际未入局 | 超额配置明确拒绝，要求调整 |
| P2 | 原静态资源中有 9 个内容为 `placeholder` 的伪 PNG；图标路径不一致 | 部分图标破图 | 服务端仅提供有效白名单资源；新界面不用伪图片，保留原目录供溯源 |
| P2 | 远端 Firebase、外部脚本/字体依赖；离线缓存不等于可靠本地多人连接 | 国内访问与断网可用性不稳定 | 自托管在线权威端；二维码依赖打包；无外部 ICE 的本地 WebRTC；缓存不存 API |
| P2 | 大型单文件、文档与实现错位、缺少可复现测试 | 修改与回归成本高 | 共用规则/后端/界面/传输分层，补规则与真实浏览器测试及部署文档 |

原版确实包含完整游戏流程与卡面，并非只有素材。但不宜原样作为公网公平游戏服务。此次保留资源与核心体验，替换运行架构，没有尝试继续连接原作者的数据库或账号。

尚未覆盖：统一 Fribench 账号、内置语音、公开匹配、聊天、广告、观战、抗房主离线作弊、跨公网无服务器 WebRTC。当前定位为朋友邀请制。没有进行真实 iOS/Android 相机、微信内置浏览器或大规模负载验收。
